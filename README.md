# XR Project 08 - Group A2 - Surfing a Gravitational Wave

Interactive XR **Digital Twin** research prototype (Unity 6000.6.3f1, OpenXR) that lets a
user observe a simplified gravitational wave from different spatial perspectives -
including a deliberately slowed *ride-with-the-wave* mode.

## Scene overview (v2)

You sit in a glass-canopy spaceship pod facing a binary black hole system. The two
holes orbit, spiral inward and merge with a flash; the emitted gravitational wave -
a chirp waveform rising in frequency and amplitude - then sweeps through a fine
three-dimensional volume of test masses around the ship and binary, visibly
stretching and squeezing the links. The volume follows the ship's viewing region
while sampling the wave at each point's world position. A stylized potential well
makes the net dip near the moving black holes; this is a visual teaching aid,
not a solution to Einstein's equations. Controls float in front of the seat;
the optional grabbable strain handle is tucked away on the left side. Ride-with-the-wave moves the whole ship
alongside the passing wavefront. The seated desktop view is attached to the VR rig's
camera inside the ship, not an independently roaming character.

In the Game view, click START MISSION on the central mission screen, or press Enter.
After the ship approaches the black holes, click CONTINUE (or press Enter) to start
inspiral and trigger the merger at simulation time 8 seconds. When piloting is
available, use WASD to move the whole ship, Q/E for vertical motion, and hold right
mouse button to look around from the seat. Click OPEN CONTROLS, or press M, to swap
the mission display for the larger mouse-operable controls; CLOSE (M) or Escape returns
to the compact mission display. Movement is disabled during scripted flight and when
the controls are expanded. In VR, the headset stays in the cockpit and XR rays use
the same controls.

## Space skybox asset

The bundled space-skybox archive is Kenney's **Skyboxes Space**, released under CC0:
https://kenney.nl/assets/skyboxes-space . Star particles use a star sprite from Kenney's
**Particle Pack**, also CC0: https://kenney.nl/assets/particle-pack . Scene regeneration
imports these textures into Assets/_Project8/Textures/Kenney/ and assigns an explicit
textured particle material, so stars cannot appear as unassigned pink squares.
The test-mass volume, nebula cards, cockpit and binary visualization are generated
by our own scripts. A material/texture can be swapped later without
changing the simulation. The fallback is the procedural starfield if no panorama
exists in the archive.

## Project brief

From "Project Requirements and Details/XR_DT_ET_Project_8.pdf" (Track A - Digital Twins &
Big Science, Einstein Telescope):

- Pedagogical strain model h(t) = h0 * sin(2*pi*f*t + phi) driving a transverse
  stretch/squeeze of freely floating test objects (ring or grid).
- Controls: play / pause / slow / replay / reset, plus amplitude and frequency.
- Two spatial viewpoints: stationary observer and a slowed ride-along perspective.
- Explicit labelling of every visualization choice (slowed speed, exaggerated strain).
- Research component: prediction task + CSV event logging + AI tutor.

## Regenerating / building the scene

Everything under Assets/ except package imports is generated by the editor scripts, so
the scene can be rebuilt at any time:

    :: 1) resolve the manifest in Unity, then import XRI samples if absent
    Unity.exe -batchmode -projectPath "<this folder>" -quit ^
      -executeMethod Project8.EditorTools.ProjectInstaller.ImportSamples

    :: 2) build/refresh both scenes, materials, prefabs and XR settings
    Unity.exe -batchmode -projectPath "<this folder>" -quit ^
      -executeMethod Project8.EditorTools.SceneBuilder.BuildAll

In the Unity Editor the same steps are on the **Project 8** menu.

## Headset setup

- OpenXR loader + interaction profiles are enabled for the Standalone target during
  scene build. Check "Project Settings > XR Plug-in Management > OpenXR" for your HMD.
- The XRI *XR Origin (XR Rig)* prefab (from the Starter Assets sample) provides
  tracked headset/controllers and the XRI Default Input Actions. Free locomotion
  providers are disabled: travel moves the ship, not a walking player.

## AI tutor

AITutor answers questions from a curated, physics-grounded knowledge base by default.
With "useRemoteBackend" enabled it calls any OpenAI-compatible chat endpoint
(`/v1/chat/completions`) and falls back to the local knowledge base if the service
is unreachable, so demos never break. Configured on the AITutor component:

| Provider | endpoint | model | key |
|---|---|---|---|
| Ollama (default, local) | `http://localhost:11434/v1/chat/completions` | `llama3.2` | none needed |
| NVIDIA NIM (free tier) | `https://integrate.api.nvidia.com/v1/chat/completions` | e.g. `meta/llama-3.1-8b-instruct` | free key from build.nvidia.com |
| Groq (free tier) | `https://api.groq.com/openai/v1/chat/completions` | e.g. `llama-3.1-8b-instant` | free key from console.groq.com |
| Azure OpenAI | `https://<res>.openai.azure.com/openai/deployments/<dep>/chat/completions?api-version=2024-02-01` | deployment name | key via env var |

The API key is read from the environment variable named in
"apiKeyEnvironmentVariable" (default `OPENAI_API_KEY`) - keys are never committed.
The LLMUnity asset is an alternative (on-device inference), but the plain HTTP
backend keeps the build small and works with any provider.

## Research data

ResearchLogger writes "session_*.csv" to "Application.persistentDataPath/Project8Logs"
with sim-time and real-time stamps for parameter changes, perspective switches,
tutor Q&A and prediction-task outcomes.
